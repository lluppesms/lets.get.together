# Get Together — Product Requirements Document (v1 / Draft for Review)

> **Status:** Draft — pending owner approval before planning/implementation begins.
> **Last updated:** 2026-08-25

## 1. Elevator Pitch

**Get Together** is a dead-simple way to organize informal gatherings with your actual friends — pickleball, a movie night, a standing coffee date, a volunteer shift — without the bloat of a public event platform. You create a **circle** of friends, post a **thing to do**, and everyone taps Accept / Decline / Maybe. That's it.

Think EventBrite, minus the ticketing, the public discovery feed, the payment processing, and the anxiety.

## 2. Background

This repository started life as a fork/copy of the `dadabase.demo` project (a .NET 10 Blazor + Azure Functions + Azure SQL + Bicep + Playwright reference app). That codebase is being repurposed — not just referenced — as the working foundation for Get Together. **Rebranding/renaming the copied code (namespaces, folder names, project names, sample data) is the first implementation task after this PRD is approved**, not part of this document's scope.

## 3. Goals

- Let a small group of friends ("a circle") see and RSVP to informal events with almost zero friction.
- Make creating an event take under a minute.
- Make it obvious, at a glance, who's in and who's out for an event.
- Keep membership closed/invite-only — this is a private tool for real friends, not a public directory.
- Reuse the existing technical foundation (Blazor Server .NET 10, EF Core + Azure SQL, Bicep IaC, Azure App Service, GitHub Actions/Azure DevOps, Playwright) rather than starting from scratch.

## 4. Non-Goals (v1)

- No ticketing, payments, or paid events.
- No public/discoverable events — everything lives inside a circle.
- No native mobile app (responsive web is sufficient for v1).
- No in-app chat/messaging (comments on an event are a possible v2 idea, not v1).
- No complex venue/booking integrations (location is a free-text field/name, not a booking system).
- No automatic scheduled reminder emails in v1 (see §7.4) — only creation notice + a manually-triggered reminder.

## 5. Personas

| Persona | Description |
|---|---|
| **Organizer Olivia** | Starts a circle (e.g., "Pickleball Crew"), invites friends, and posts most of the events. Wants creating an event to be fast. |
| **Casual Casey** | Gets invited into a couple of circles, mostly just RSVPs. Wants a quick way to see "what's happening" without digging. |
| **New Friend Nate** | Was given a one-time invite code by Olivia. Wants signup to be quick and to land straight in the right circle. |

## 6. Core Concepts / Data Model (conceptual, not schema)

- **User** — a person, authenticated via an external identity provider. Has a display name and email (from the provider).
- **Invitation Code** — a single-use code generated by an existing member, tied to a specific circle, used once to let exactly one new person join that circle during signup.
- **Circle** — a private group of friends (e.g., "Pickleball Crew", "Neighborhood Coffee"). A user can belong to many circles. Circles do not see each other's events.
- **Event** — something happening: a title, description, location (free text), start date/time, optional end date/time, and the circle it belongs to. Two kinds:
  - **One-off event** — happens once (e.g., "Watch Spider-Man — Friday 7:00 at the Marcus Theatre").
  - **Recurring event** — happens on a repeating schedule (e.g., "every Saturday at 8:00am"). The creator chooses, per event, whether attendees RSVP once for the whole series or per occurrence (see §7.3).
- **RSVP** — a user's response (Accept / Decline / Maybe) to a specific event (or a specific occurrence of a recurring event).

## 7. Functional Requirements

### 7.1 Authentication & Onboarding
- Sign-in supports **Google, Microsoft (Entra ID), and Facebook** as external identity providers. No app-managed passwords.
- New users must supply a valid, unused **invitation code** to complete signup. The code is generated by an existing member for one specific new person, is tied to one circle, and is consumed on first successful signup.
- Any existing member of a circle can generate an invitation code for someone else to join that circle. There is no separate "admin-only" restriction on invite generation for v1.
- After signup, the new user lands directly in the circle their invite code was tied to. They may be invited into additional circles later via additional codes.

### 7.2 Circles
- A user can belong to any number of circles.
- Circles are independent: events, membership, and invite codes in one circle are not visible from another.
- Any member of a circle can see the full member list of that circle.
- v1 does not require a formal "circle admin" role — every member has equal standing (create events, invite others). Revisit if abuse/moderation needs emerge.

### 7.3 Events
- Any member of a circle can create an event in that circle.
- Creating an event requires: title, date/time (start; optional end), location text, and optional description/notes.
- The creator chooses whether the event is:
  - **One-off** — a single date/time.
  - **Recurring** — a repeating rule (e.g., weekly on a given day/time). For recurring events, the creator also chooses the RSVP mode:
    - *Per-occurrence* — attendees RSVP separately to each week's instance (default; supports "I can make it this week but not next").
    - *Series* — a single RSVP applies to the whole series ("I'm in every week").
- Event creation triggers an email notification to all circle members (see §7.4).
- Any circle member (not just the creator) can view an event's full RSVP roster: who accepted, declined, or is still undecided.

### 7.4 RSVPs & Notifications
- RSVP options are **Accept / Decline / Maybe**.
- When a new event is created, all circle members receive an **email notification** (via SendGrid) with the event details and a direct link to RSVP.
- The event creator (or any member — TBD in planning) can **manually trigger a reminder email** to members who haven't yet responded, or to everyone. No automatic scheduled reminders in v1.
- Members can change their RSVP at any time before the event.

### 7.5 Calendar
- A calendar view shows all upcoming events across every circle the signed-in user belongs to.
- Two view styles are supported: a **month grid** (with day drill-down) and an **agenda/list view** grouped by date.
- Each circle's events are visually distinguishable (e.g., by color or circle label) when viewing the combined calendar.

## 8. Non-Functional Requirements

- **Platform**: Responsive web app; must be comfortably usable on a phone browser. No native app or installable PWA required for v1.
- **Architecture**: Reuse the inherited Blazor Server (.NET 10) + EF Core/Azure SQL + Bicep + Azure App Service + GitHub Actions/Azure DevOps + Playwright stack. Rebranding of namespaces/folders/solution names happens as the first implementation task, after this PRD is approved.
- **Email delivery**: SendGrid.
- **Privacy**: This is a private tool for real friends. No public event listing, no search-engine indexing of event content, no anonymous access to circle data.
- **Data ownership**: Circle data (membership, events, RSVPs) must never be visible to users outside that circle.
- **Testing**: Preserve the existing testing posture inherited from the source repo — xUnit tests for services/repositories, Playwright for browser smoke/E2E coverage — updated to exercise circles/events/RSVPs instead of jokes.

## 9. Open Questions (to resolve during planning)

- Who besides the creator can manually trigger a reminder email — any member, or only the creator?
- What happens to future occurrences of a recurring event if a member leaves the circle?
- Should there be any limit on how many invitation codes a member can generate, to reduce spam/abuse risk?
- Should declined/expired invitation codes be visible to the member who generated them (for cleanup)?
- Exact recurrence rule vocabulary (e.g., weekly on weekday X, biweekly, monthly) — full RFC5545/RRULE support vs. a simplified subset.

## 10. Out-of-Scope Ideas for Later (v2+)

- In-app comments/discussion per event.
- Circle admin roles / moderation tools.
- Automatic scheduled reminders (e.g., "24 hours before").
- Photo/media sharing per event.
- Native mobile app or PWA install.
- Public/discoverable circles or events.

## 11. Success Criteria

- A new member can go from receiving an invite code to seeing their circle's calendar in under two minutes.
- Creating an event takes under a minute for a returning member.
- At a glance, any member can tell who's in, who's out, and who hasn't answered for a given event.
